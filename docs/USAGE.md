# 使用说明

启动方法见 [部署说明](DEPLOY.md)。

1. 打开前端，设置企业要求和设备参数，点击生成日前计划。
2. 查看96点预测、日前储能/SOC/购电计划。
3. 点击“Execute next 15 minutes”，只执行一个时段；或选择自动运行。
4. “Pause”在当前一步保存完毕后暂停；刷新页面不会重复执行时段。
5. 查看预测评估、费用、峰值和执行结果，在“Records & export”导出完整JSON。
6. 点击“Open this plan in Grafana”，打开相同方案与正确UTC日期的看板。

更改要求后需生成新方案，旧方案保留。后台自动运行不依赖页面保持打开。
0.2秒等选项只是播放速度，每步始终对应15分钟。

## 约束与目标

功率平衡：光伏 + 购电 + 放电 = 负荷 + 售电 + 充电 + 弃光。
SOC按充放电效率和0.25小时计算，禁止同时充放电、同时购售电。
硬约束包括SOC范围、备用SOC、末端SOC、充放电功率和设备购售电容量。
企业购电软目标可超出，硬上限不会自动放松；不能供电时停止并给出冲突原因。

按固定顺序求解，不提供优化权重：

1. 启用软目标时，最小化超标电量。
2. 削峰模式下，最小化购电峰值。
3. 保持前面最优值，最小化电费与固定电池损耗成本。

电费指标不含简化的电池损耗惩罚。单步决策假定当前15分钟平均实际功率已知，
这是离线仿真假设，不能直接解释成现场实时控制。

## Grafana

看板自动配置，无需手动导入JSON。选择方案，或从前端跳转。
曲线分别显示日前、最新滚动、已执行结果；只会出现已执行的实际观测。
图表默认每5秒刷新，使用UTC日期；手动选择历史方案时也要选对应的日期范围。
前端链接会自动设置该日期，避免历史方案落在默认“今天”范围之外。

Grafana的数据源通过Docker服务名 `influxdb:8086` 连接，不连接宿主机旧服务。
部署配置中 `EMS_GRAFANA_URL` 必须是访问者浏览器能够打开的地址。

## API

API仅在Docker网络内提供服务，接口文档为API容器的 `/docs`。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/health` | 检查后端与存储 |
| GET | `/api/scenarios` | 模型评估场景信息 |
| POST | `/api/simulations` | 生成新方案 |
| GET | `/api/simulations` | 方案列表 |
| GET | `/api/simulations/{id}` | 状态及公开历史 |
| POST | `/api/simulations/{id}/step` | 传入expected_step，执行下一步 |
| POST | `/api/simulations/{id}/start` | 传入interval_seconds，自动执行 |
| POST | `/api/simulations/{id}/pause` | 暂停 |

重复执行或约束不可行返回409；非法输入返回422；存储不可用返回503。
